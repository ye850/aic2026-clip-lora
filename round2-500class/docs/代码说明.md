# 代码说明

## 一、这个目录里有什么

```
代码与数据/
├─ src/                    模型与训练/推理的核心模块（16 个）
│   ├─ config.py           全局配置与路径解析（全部来自环境变量，无硬编码绝对路径）
│   ├─ data.py             数据集扫描、类别映射、提交文件写出
│   ├─ lora.py             LoRA 旁路注入
│   ├─ finetune_lora.py    训练主流程（LoRA + SAM + EMA + SWA + SCE + KD）
│   ├─ sam.py / asam.py    平坦极小优化
│   ├─ extract.py / train_head.py / predict.py / pipeline.py
│   ├─ noise.py / swa_lookahead.py / vpt.py / adapter.py / region_attention.py / zeroshot.py
├─ scripts/                复现与训练入口（8 个，见下表）
├─ _meta/                  训练元数据（类别表 train_meta.json / 软冲突组 / 尺子标签）
├─ Dockerfile              复现镜像定义（只含环境）
├─ requirements.image.txt  依赖锁定（与产出提交包的机器一致）
├─ .dockerignore
├─ docker-compose.yml      数据/模型/代码的宿主机挂载编排
├─ reproduce_submit.sh     一键复现（含 md5 比对）
├─ verify.sh               镜像与复现的验证脚本
├─ 数据说明.md              数据结构、规模、挂载方式、合规声明
└─ 技术方案_源文件.md        技术方案的 Markdown 源（PDF 由它生成）
```

## 二、scripts 里的 8 个文件，各管一段

| 文件 | 作用 | 复现要用 | 重训要用 |
|---|---|:--:|:--:|
| `predict_tta.py` | **推理入口**：25 视图 TTA，产出 `probs.npy` | ✅ | |
| `tta_lora_eval.py` | 模型构建 / LoRA 加载 / 25 个视图定义 / 批量推理 | ✅ | |
| `calib_sinkhorn_apply.py` | 概率校准（Sinkhorn，目标分布均匀） | ✅ | |
| `check_submission.py` | 提交文件合规校验（行数/类覆盖/格式） | ✅ | |
| `compare_lora_vs_frozen.py` | 特征提取工具（被 `tta_lora_eval` 引用） | ✅ | ✅ |
| `arm_runner.py` | **训练入口**（组装 argv 调 `finetune_lora`） | | ✅ |
| `eval_acc.py` | 在固定留出集上计算准确率（本地评估用） | | ✅ |
| `model_soup.py` | 权重平均（**已实测为负，保留仅为记录**） | | 可选 |

> 比赛期间还写过大量探针/诊断/对照脚本（用于定位各类负结果）。那些是排雷工具，
> 不属于复现链，**未随本包提交**，以免混淆主干。

## 三、复现只需要三样东西

```
① 代码  = 本目录
② 模型  = ../模型目录/fd560v2_best.pt
③ 数据  = 组委会提供的测试集（49,857 张，扁平目录，文件名即提交 ID）
```

按 `docker-compose.yml` 挂载后执行：

```bash
bash reproduce_submit.sh
```

内部就是三步（可单独调用）：

```bash
# 1) 25 视图 TTA
python scripts/predict_tta.py --lora <权重> --views <25 个视图> \
       --out-dir <输出> --save-probs <输出>/probs --force --workers 0

# 2) Sinkhorn 校准（iters=15，目标均匀）
python scripts/calib_sinkhorn_apply.py --probs <输出>/probs.npy \
       --out-dir <输出>/pack --target uniform --iters 15 --force

# 3) 校验
python scripts/check_submission.py <输出>/pack/pred_results.zip
```

## 四、路径与配置：全部来自环境变量

代码里**没有任何写死的绝对路径**。所有位置由以下变量决定（`src/config.py` 统一解析）：

| 变量 | 含义 | 复现时取值 |
|---|---|---|
| `AIC_ROOT` | 工程根（`data/`、`outputs/` 都在其下） | `/workspace/aic` |
| `AIC_CLIP_DIR` | CLIP 官方权重目录 | `/workspace/aic/models/clip-vit-base-patch32` |
| `AIC_IMG_SIZE` | 推理分辨率 | `560`（与权重内的 `img_size` 一致） |
| `AIC_STAGE` | 赛段声明，用于阶段隔离护栏 | 默认 `半决赛` |
| `AIC_CKPT` | 权重路径（`reproduce_submit.sh` 用） | 默认取模型目录下的 `fd560v2_best.pt` |

> `src/config.py` 里内置了一道**阶段隔离护栏**（默认开启）：若 `AIC_ROOT` 指向的阶段
> 与声明的 `AIC_STAGE` 不一致，会直接报错退出而不是静默运行。
> 本作品的数据集为 **500 类**，与该护栏的对照表一致（`{500: 半决赛, 750: 复赛}`），
> 正常复现不会触发。

## 五、不随包的东西

| 项 | 原因 |
|---|---|
| 赛题数据（训练 90,152 / 测试 49,857）| 由组委会提供，不应随作品分发 |
| CLIP 官方权重（578 MB）| OpenAI 官方产物，可自行下载 |
| 其余 28 个训练臂的权重 | 结论已在《负结果与判死方法》中，权重本身无复用价值 |
| 比赛期的探针/诊断脚本 | 排雷工具，不属复现链 |
