## 一、先说我自己犯的两个判据错误（这一节比结论重要）

```

  s_own∈[0.5,0.9):  n=  558  acc=1.0000   ← 只有 0 与 1
```

★ **而且这个判据在真实使用场景里根本算不出来** —— 上传时**没有标签**，
`s_own`（对标签的后验）无法计算。**一个无法在上传时计算的东西，不能作为筛选取据。**

## 二、实测结果（`scripts/_probe_filter_viability_v3.py`，2.0s，纯 CPU）


```
n=7537  base acc=0.8344
rank(真类)：中位 1.0   ≤5=0.9245   ≤10=0.9422   >100=0.0199
```

### 2.1 循环性自检（哪些信号是同义反复）

| 信号 | corr(信号, 对错) | 低半 acc | 高半 acc | 判定 |
|---|---|---|---|---|
| A1 视图一致性 `agree` | **+0.5828** | 0.4606 | 0.9412 | ⚠️ 中度绑定 |
| A2 集体确信度 `conf` | **+0.6544** | 0.6814 | 0.9873 | ←★ 高度绑定 |
| A3 视图负熵 | **+0.6354** | 0.6818 | 0.9870 | ←★ 高度绑定 |
| C `s_own`（对照） | **+0.9460** | 0.6688 | 1.0000 | ←★ 几乎完全绑定 |

⇒ ★★ **A2/A3/`s_own` 与"对错"高度绑定 ⇒ 有标签时是同义反复，无标签时算不出来。**
⇒ 只有 **A1（视图一致性）相关性最低（0.583）**，是这几个里唯一有独立信息的。

### 2.2 ★★★★★ 核心判据：最可疑那批的 rank 结构（**结论与我的预期相反**）

```
  全体基准：rank≤5 = 0.9245   rank>100 = 0.0199

  信号          筛掉k%     n    该批rank≤5   该批rank>100   该批acc   lift(≤5)
  A1 agree       5%     376     0.6064      0.1011     0.1649     0.66x
  A1 agree      10%     753     0.6321      0.0890     0.2417     0.68x
  A1 agree      20%    1507     0.7266      0.0657     0.4287     0.79x
  A2 conf        5%     376     0.4468      0.1356     0.1410     0.48x
  C  s_own       5%     376     0.0904      0.3989     0.0000     0.10x
```

**判读（★ lift < 1x 是关键）**：
- 「最可疑 5%」里 `rank≤5` 占比 = **0.6064**，而全体是 **0.9245**
  ⇒ **lift = 0.66x（远小于 1）**
- ⇒ ★★★★★ **最可疑的那批，恰恰"最不可能差点就对"。**
  它们不是"排名第二三名的近亲"，而是**真类根本不在前 5** 的样本。

⇒ **"加权/优化这些低置信样本"很可能是无效的** ——
  因为它们的问题不是"选择错误"，而是"模型对它们毫无表示”。
  ★ 这与"缺的是选对"这个此前的判断**方向相反**（那个判断基于全体错样本）。

### 2.3 诊断：错样本的真类 rank 分布

```
  错的样本 n=1248（占 0.1656）
    rank 2~5      n=  679  占错样本 0.5441   ← 主体
    rank 6~10     n=  133  占错样本 0.1066
    rank 11~50    n=  216  占错样本 0.1731
    rank >50      n=  220  占错样本 0.1763
```

⇒ ★ **全体错样本里，rank 2~5 占 54.4%** ⇒ "前几名选错"确实是错分主体
   ⇒ 支持"推理侧/排序侧有空间"。
⇒ ❗**但 2.2 显示：最"可疑"的那批并不落在这里** ⇒
   两件事不矛盾：**错分主体是"差点就对"，但"模型自己知道可疑"的那批不是。**
   ⇒ **这意味着"用置信度去挑样本"和"错分主体"错位了。**
