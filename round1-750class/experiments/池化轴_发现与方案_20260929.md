## 一、发现：patch token 从未被使用

### 事实（附源码位置，可复核）

全项目的**所有**图像特征入口都走同一个调用：

| 位置 | 代码 |
|---|---|
| `src/extract.py:147` | `take_embeds(model.get_image_features(pixel_values=..., interpolate_pos_encoding=...))` |
| `src/finetune_lora.py:287` | 同上（`encode()` 方法） |
| `src/vpt.py:455` | 同上 |

而 `get_image_features` 的内部实现（transformers）等价于：

```
vision_model(pixel_values) → pooler_output        # = CLS token 过 post_layernorm
                           → visual_projection    # 投影到 512 维文本空间
```

**关键**：`pooler_output` 只等于 `last_hidden_state[:, 0]`（CLS）。
⇒ `last_hidden_state[:, 1:]` 即 **patch token 从未被读取过一次**。

### 量级

- ViT-B/32，IMG_SIZE=448 ⇒ patch 网格 `448/32 = 14` ⇒ **14×14 = 196 个 patch token**
- 每个 768 维 ⇒ 一整块 **196×768** 的表征被丢弃，只用了 1×768 的 CLS。

### 为什么这算"真空白"而不是"调参"

| 维度 | 调参（已放弃） | 池化（本次） |
|---|---|---|
| 改的是什么 | 学习率/权重衰减/混合比例 | **特征如何从骨干汇聚出来** |
| 是否动输入 | 否 | 否（**不毁 TTA 视图一致性**） |
| 类比 | 拧旋钮 | 换零件 |
| 本地尺可信度 | 模型类 ⇒ 可信 | **模型类 ⇒ 可信**（看低相似列） |

★ 与"已排除的几何增强"的本质区别：几何增强改的是**输入**（会毁 TTA 多视图一致性）；
池化改的是**聚合**（输入不变，TTA 视图仍一致）⇒ 不冲突。

## 二、四种池化的设计

| 名称 | 公式 | 是否在 CLIP 文本空间 | 风险 |
|---|---|---|---|
| `cls` | `h[:, 0]` | ✅（原行为） | 基准 |
| `mean` | `mean(h[:, 1:])` | ✅（过 post_ln + proj） | 低 |
| `gem` | `(mean(h[:,1:]**p))**(1/p)`，p=3 | ✅（过 post_ln + proj） | 低 |
| `attn` | `softmax(q·kᵀ/√d) @ v`，q=h[:,0], k/v=h[:,1:] | ✅（过 post_ln + proj） | 低 |
| `gem + multi` | `cat(gem(hs[6]), gem(hs[9]), gem(hs[12]))` → 2304 维 | ❌ **不在文本空间** | 高 |

**注意 attn 的取舍**：这里用 `h[:, 0]` 自身作 query、**不引入可学习权重**
⇒ 它是"按 CLS 与各 patch 的相似度加权"的**纯几何操作**，不增加训练参数。
好处是单变量干净；代价是表达力弱于真正的 learnable attention pooling。
（若 `attn` 表现好，下一步可升级为带可学习 q/k 的版本。）

**multi 的取舍**：多层拼接后 768×3=2304 维已不在 CLIP 文本空间，
CLIP 的零样本对齐能力**在这条路上用不上**，分类头必须从零学。
⇒ 它是"更激进的换做法"，排在 `gem` 之后作为风险递进档。

## 三、执行结构（三处接线，全部强制自证）

本项目已因"接线铺好 ≠ 参数生效"栽过三次
（`ls01` 的 label_smooth 被静默丢弃 / `night_arm` 自检通过但下游不用 / SupCon-v1 空转）。
本次**每一处都加了失败即拒绝的守卫**：

| # | 接线点 | 自证方式 | 失败后果 |
|---|---|---|---|
| 1 | CLI 收参数 | `--pool` / `--pool-multi` 存在性检查 | 补丁检查不通过 |
| 2 | 训练侧构造模型 | 日志必须打印 `[pool] ★ 启用非默认池化` | **退出码 2，判失败** |
| 3 | 出包侧构造模型 | 日志必须打印 `[tta] ★ 按训练配置恢复池化` | 无此痕迹则告警 + 人工核查 |

★★★ **第 3 处是最险的**：生产出包走的是
`predict_tta.py` → `scripts/tta_lora_eval.py:238`，
**不是** `src/finetune_lora.py:1461`（那是 `--predict-only` 路径）。
最初我漏了 `tta_lora_eval.py`，若就这么跑下去：
训练用 gem、出包用 cls ⇒ `head` 维度不符 ⇒
`load_state_dict(strict=False)` **静默丢弃分类头** ⇒ 输出近乎随机、榜分暴跌且极难归因。

⇒ 现在两处都改了，且都加了"分类头未落地即 `SystemExit`"的硬守卫。

## 五、判据（明早怎么看）

1. **探针结论**（`outputs/pool448_probe.log`）：
   若 `mean`/`gem`/`attn` 相比 `cls` 出现 **≥0.5pp** 的 kNN 增益
   ⇒ 说明 patch token 确实含 CLS 没捕获的信息 ⇒ 训练臂的预期收益有依据。
   若三者在 ±0.5pp 内 ⇒ 说明 CLS 已足够，训练臂大概率无增益
   （但仍实测确认，因为探针是冻结特征、训练是端到端，两者不等价）。

2. **训练臂读数**（`outputs/r448poolgem_run.log`）：
   - 与**基准 r16 的 0.7706** 比（同为一处改动）
   - ★ 按项目的"尺子分层"结论，池化属**模型类改动** ⇒ **本地尺可信**，
     重点看 **低相似列**（不是总 val_acc）
   - 基准低相似参考：r32 峰值 0.6546（ep6）

3. **出包自检**：
   `grep '\[tta\] ★ 按训练配置恢复池化' outputs/r448poolgem_run.log` 必须有输出。
   若无 → 包**不可交**（可能是按 cls 出的，与训练不一致）。
