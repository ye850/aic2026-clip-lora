# 按文件 hash 分组的切分设计（修正 OOF 泄漏）
> 2026-10-06 ｜ 依据：`outputs/文件级重复标签冲突_确定错误.json`（1,877 组 / 3,884 张，
> 已由 SHA-256 逐字节复核）｜用户 10-06 复核发现 OOF 存在**跨折重复污染**

---

## 一、要修的问题（用户复核确认）

用户按留存切分规则 + 默认 seed 重建折号，路径核对 OOF 标签**吻合率 100%**，得到：

| 项 | 数量 |
|---|---|
| 冲突组中**跨折**的组 | **1,535 / 1,877** |
| 涉及样本 | **3,198 / 3,884** |
| 其中 OOF 错分 | 2,633 张 |
| ★ 被预测成「训练折中那个同字节副本」的冲突标签 | **2,027 张** |

⇒ **同一张图在训练折里以另一个类别的副本出现** ⇒ OOF 样本的预测被"见过同字节、异标签"的模型污染。

---

## 二、根因

现有切分是**逐样本随机**（`src/data.py:build_train_manifest()` 的行序 + 按位置抽 val），
**没有做分组约束** ⇒ 同字节副本被分到不同折。

**为什么这在 OOF 里特别致命**：
- 普通近似重复（不同文件、同物种）跨折 ⇒ 污染有限
- **同字节副本跨折** ⇒ 模型在训练折里**逐像素见过这张图**，只是标签不同
  ⇒ 留出折里它面对的是"训练时见过的图 + 冲突标签" ⇒ 预测结果**不是泛化能力**

---

## 三、设计：GroupKFold by file hash

### 3.1 核心原则
**凡 file md5 相同的样本，必须落在同一折**（要么全留出、要么全进训练）。

### 3.2 实施步骤

```
Step 1  为全部 148,695 个训练文件算 md5（已做，耗时 ~90s；只按文件大小分组以省哈希）
Step 2  聚成 group：G = {g1, g2, ...}，同 md5 的样本属于同一 group
        实测：2,128 个 md5 重复组（4,386 张）⇒ 其中 1,877 组标签冲突
Step 3  切分单位从「样本」改为「group」：
        · 对 group 分配 fold，而非对样本
        · 保持每折样本量尽量均衡（贪心：按当前各折容量，从小到大放）
        · 保留 val「每类至少 8 张」的约束（沿用 finetune_lora 的 val_per_class）
Step 4  记录 fold 号到 manifest（新增列 `fold`），供 OOF 与 val 复用
```

### 3.3 必须保持不变的口径（避免又造新变量）
| 项 | 值 | 为什么不能动 |
|---|---|---|
| seed | 0 | 与冠军配方一致 |
| val 比例 | 5%（7,537） | 变了会和历史读数不可比 |
| val 划分 | 每类至少 8 张 | 沿用 `finetune_lora` 现有逻辑 |
| 训练配方 | CHAMP_BASE + `--hidden 1024 --kind sce` | 唯一变量只能是切分 |

---

## 四、这个设计能回答什么 / 不能回答什么

### ✅ 能回答
1. 在**无同字节泄漏**的 OOF 上，头部类别对撞（`0179↔0247` 等）还剩多少
   —— 若剔除污染后对撞基本消失，则那批"混淆"确实是数据缺陷，不是视觉混淆
2. 无污染 OOF 上的加权 skew（用户已初步复算：0.5345 → **0.5504**，仍 < 0.65）
3. 后续任何"标签可靠度"方法，应在**这个干净 OOF** 上做才有意义

### ❌ 不能回答
1. **不修正标签** ⇒ 不改变训练 ⇒ 不能带来分数
2. 剩余 22% 的 OOF 错分**不是**同字节重复造成的（用户复算 skew 仍 0.55）⇒ **主因仍未定位**
3. 不解决"哪个标签才对"的问题（无物种名，见下）

## 五、与"修正标签"的关系（严格区分两件事）

| 方案 | 作用 | 现状 |
|---|---|---|
| **A. 按组切分** | 只改**评估口径**，让 OOF/val 不被泄漏 | ★ **可以先做**（零风险，零 GPU 只需改切分代码） |
| **B. 去重/限权** | 改**训练**，减少矛盾监督 | ⏸ **须先确认赛规允许调整训练标签**，且需设计正确（见下） |

### B 的正确设计（用户 10-06 指出我原方案无效）
我原来的想法"给同组软标签分布"是**无效**的：把软分布复制给组内每张图、保留原总权重，
合计梯度**基本等价于原冲突硬标签总和**。真正能减少矛盾监督的只有两种：

| 做法 | 机制 | 代价 |
|---|---|---|
| **B1 按 hash 合并去重** | 同组只保留 1 条样本 | 丢失 (n−1) 条信息；且**仍需选一个标签**（无物种名 ⇒ 只能按多数或随机） |
| **B2 限制每组总权重** | 组内每张权重 1/n，总权重不变 | 矛盾方向仍在，只是幅度减小 |

⇒ 二者都**无法回避一个硬约束**：**没有物种名，就无法判断组内哪个标签正确**。
⇒ 而软目标分布**只是观察到的标签比例，不代表真实类别**（用户 10-06 明确）。

## 七、结论

- **立刻可做（零 GPU、零风险）**：把切分改成按 file hash 分组
  → 得到**干净的 OOF/val 口径**，这是后续一切"标签可靠度"研究的前提
- **必须先确认赛规**：改标签是否允许；提交规则；复赛权重
- **不要再投入**：CLIP 视觉近重复统计（用户已叫停）、"纯短边/校准/头部调参"（已判负/饱和）
- **仍诚实承认**：**2.94pp 缺口的主因未定位**。已确认的标签缺陷（1.35% 标签不一致）填不动它；
  排除重复后 OOF skew 仍 0.55（< 0.65）⇒ **没有证据支持大规模单向改标签**
