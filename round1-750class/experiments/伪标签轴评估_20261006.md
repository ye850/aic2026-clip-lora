## 1. ★★ 最关键的发现：置信度被 float16 量化摧毁

`outputs/pseudo/probs_train.npy` 是 **(141158, 750) float16**。

float16 在 1.0 附近的分辨率是 **2⁻¹¹≈ 4.88e-4**。实测：

| 量 | 值 |
|---|---:|
| `conf ≥ 0.9999`（=已饱和到分不出）的样本占比 | **78.57%** |
| 一致率（全池，打标器 vs 已有标签） | 95.0354% |

⇒ **「模型真置信 0.9998」与「模型真置信 1.0000」落盘后不可分。**

**后果**：τ ∈ [0.9, 1.0] 的阈值在这份数据上**没有判别力**。
实测 τ 曲线的平坦段全是量化产物：

| τ | 覆盖率 | 覆盖率内一致率 |
|---:|---:|---:|
| 0.50 | 99.64% | 95.2825% |
| 0.80 | 96.77% | 96.6955% |
| **0.90** | **95.04%** | 97.3053% |
| 0.99 | 88.94% | 98.4977% |

⇒★ **当时 pl3 用的「τ=0.9 筛高置信」，实际等于「几乎不筛」**（留下 95.04%）。
这个筛选**从来没真正生效过**。

⚠️ **与出包链路同一个病**：记忆里已记「概率存 float16 ⇒ 99.03% 元素为 0」。
这次在伪标签这条路上**再现了同一个缺陷**。

## 2. ★ 唯一未被污染的判据：模型与原标签不一致

既然 conf 不可用，改用**不依赖置信度**的事件本身：

| 量 | 值 |
|---|---:|
| 打标器与训练集已有标签**不一致**总数 | **7,008 张（4.965%）** |
| 这批的 conf 中位 | 0.9082 |
| 这批里conf < 0.9 占 | 48.4% |
| 这批里 conf 已饱和占 | 9.9% |

⇒ ★★ **9.9% 的不一致样本是"模型很确信但与标签不同"** ⇒ 仍可能是真错标
（**模型对≠ 标签对**，这两件事不等价）。

**不一致最集中的类别**：

| 类 | 不一致 / 该类总数 | 比例 |
|---:|---:|---:|
| 640 | 129 / 186 | **69.4%** |
| 364 | 120 / 233 | 51.5% |
| 535 | 77 / 151 | 51.0% |
| 232 | 87 / 189 | 46.0% |
| 603 | 98 / 215 | 45.6% |

⇒ 这不是随机散布，**高度集中在少数类**⇒ 与 §4.7「低相似指向具体类」的读数方向一致。

## 3. ★★★ 唯一能证伪的一刀：与 md5 冲突组的交集

`文件级重复标签冲突_确定错误.json`（1,877 组 / 3,884 张）里的样本
**被 md5 独立证实是错标**——这是**独立于模型**的证据。

⚠️ **踩坑**：两边路径前缀完全不同，直接比字符串**一条都对不上**：

| 来源 | 路径格式 |
|---|---|
| md5 清单 | `D:\AIC复赛\data\train\train\0270\<md5>.jpg` |
| pseudo 索引 | `/root/autodl-tmp/aic/data/train/0000/<md5>.jpg` |

⇒ 修法：**basename 桥接**。先自证 basename 唯一性：
**141,158 个 basename，重复 0 个** ⇒ 可安全桥接。

| 量 | 值 |
|---|---:|
| 桥接命中 | **3,686 张**（未命中 198） |
| ★ **其中模型也判不一致** | **1,929 张 = 52.3%** |
| ★ **含≥1 张不一致的组** | **1,717 / 1,877 = 91.5%** |

⇒ ★★★ **91% 的冲突组，模型也认为其中有标签是错的。**
⇒ 这是**伪标签最该改的一批**，且有 md5 作为独立证据（不依赖模型自己的判断）。

## 4. 处置路线对比（这才是可决策的）

候选池7,008 张，两种用法：

| 路线 | 做法 | 代价 |
|---|---|---|
| **A. 改标签**（pl3 走的） | 7,008 张标签换成伪标签 | 不损失监督量 |
| **B. 丢样本** | 7,008 张不参与训练 | 少 **4.965%** 监督量 |

⇒ ★ A 相对 B 的**机制优势是真的**：不丢监督量。
而 `r32`（减容量）已实测 **−1.81pp** ⇒ B 天然吃亏。
⇒ **这是 pl3 唯一站得住的地方。**

## 5. ⇒ 结论

###5.1 先验值：**给不出正数**

| 项 | 读数 |
|---|---|
| pl3 榜上实测 | 70.6121 vs 裸 ul4 71.4988 = **−0.89pp** |
| 打标器质量 | 老臂 `d_r448up`（榜分 **70.55**），不是 U 冠军 **75.26** |
| 当前数据可用性 | ❌ conf 被float16 摧毁，τ 无判别力 |

⇒ 机制上「好打标器 ⇒ 好伪标签」成立，但**幅度未知**。
⇒ 按铁律 146（先验 ≥0.3pp 才发车），**这条路当前不满足门槛**。

### 5.2 ★★ 但有一个**新的、可操作的**结论

**与md5 冲突组 52.3% 的交集（1,929 张）是这条路唯一有独立证据支撑的部分。**

⇒ 精确表述应该是：
- 「**用伪标签大规模改标签**」⇒ 无先验，pl3 已证−0.89pp
- 「**只改md5 已证实错标的那 1,929 张**」⇒ **完全是另一件事**，
  有 md5 独立证据、不依赖模型判断、不依赖 conf 阈值

⇒ ★★ **后者从未被测过**，且它比pl3 做的事**精确得多**
（1,929 张 vs pl3 的 3,613 张回收，且pl3 的 τ 筛选根本没生效）。

### 5.3 前置条件（不满足就做不了）

⚠️ **重跑打标必须以 float32/float64 落盘概率**。
现有 float16 落盘使**任何基于 conf 的筛选/加权都做不出来**。
这是**出包链路那个缺陷的同一个根因**，建议一次性修掉。
