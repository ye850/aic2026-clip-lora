## 1. ⚠️ ① float16：**撤回本节原先的定量结论**（10-06 14:30 用户复核后修正）

### 1.1 ★ 撤回什么（我的错误结论）
| 原结论 | 状态 | 撤回理由 |
|---|---|---|
| "floor 跨 24 个数量级，最多影响 1981 张 = 5.29pp" | 🛑 **撤回** | **人工设floor ≠ 还原真实 float32 概率**。fp16 下溢成 0 的元素，真值并不相同（分布在 1e-30 以下各量级）；统一替换成同一个 floor 制造的是**人造分布**，不是 fp32 真实分布 ⇒ 扫描结果既不能证明上界，也不能证明下界 |
| "期望净收益 ≈ 0（改变双向）" | 🛑 **撤回** | 无任何证据支持"双向"。我把它当成了默认假设 |
| "float32 不值得占提交机会，只用于审计" | 🛑 **撤回建议** | 建立在上面两个已撤回的结论上 |
| "margin 分析证明翻不了" | 🛑 **撤回** | ★ **该脚本比较的是校准前的 top1/top2**，而实际预测是 `argmax(log p + b)`，**类偏置 b 会改变排序** ⇒ 结论不成立 |

### 1.2 仍然成立的只有这两条
1. **事实**：fp16 存盘确实丢信息 —— 99.03% 元素为 0，最小非零 5.958e-08（＝fp16 最小 subnormal）。
2. **事实**：这些 0 在 `log(max(p,1e-30))` 下被替成 log = −69.08。**影响方向与量级：未知。**

⇒ ★ **当前证据只能支持一句话：fp16 会丢信息，榜分影响未知。**（既不能说≈0，也不能说 5.29pp）

### 1.3 唯一能定论的做法（用户指出，正确）
必须**对同一ckpt 重新推理并保留真实 float32 概率**，再走同一条 Sinkhorn：
```
predict_tta.py 存float32→  calib_sinkhorn_apply.py（同一 --target/同参数）
⇒ 与现役 fp16 包逐位对比
```
- 人工加 floor 的扫描**不能替代它**（人造分布 ≠ 真实分布）；
- 只需**重出包、不重训**（ckpt 现成：`cloud_ckpt/d_r512_best.pt` 旁有 B 臂 ckpt，U 臂 ckpt 在云端已拉回）；
- 成本：一次推理 ≈ 16 min。

### 1.4 附带保留：两版诊断脚本的正确用法与错误示范
- `outputs/_diag_sinkhorn_floor2.py`：可复用为**口径匹配的操作自证**（证明"b 与 logp 必须同口径"），
  ⚠️ **不可当作 fp32 影响量的估计**。
- `outputs/_diag_f32_margin.py`：⚠️ **有缺陷**（用校准前 margin，未计入 b）⇒ 保留作为反面记录，
  修复前不得引用其数值。
- ⇒ 立**铁律 108**（同口径）、**110**（不可用人工替换冒充真值分布）。

## 2. ★②的根因（比用户描述更具体）

**清单结构不匹配**（我取证时发现的额外事实）：
- `outputs/文件级重复标签冲突_确定错误.json` 字段 = `paths` / `labels`（**无 members/weight_each/soft_target**）
- ★ **U 臂实际用的是另一个转换后文件** `outputs/dedup_soft_conflicts.json`（由 `chainU_softconf.sh:41` 指定），字段 = `group/n_members/labels/weight_each/weight_total/soft_target/members`✅ 匹配
- ★ **该文件里没有任何"该成员是否在 val"的标记** ⇒ `finetune_lora.py:915-917` 按全量 `_m[_base(mem.path)]` 建表，**必然把 val 副本的标签算进训练样本的软目标**。

**影响量级**：3,884 张受影响样本 / 148,695 = **2.61%**；涉及 1,877 组、352 类。
- U臂本地 val 曲线（7,537 张）中真正被污染的比例：**未知但不为 0**。
- ⇒ ★ **不推翻 U 的榜分75.2564**（测试集预测不受val 影响），但**本地曲线与选epoch 不可靠** ⇒与用户判断一致。

**修法（零训练成本）**：建表时按 `~val_mask` **再过滤一次组成员**，组总权重按**留在训练侧的成员数**重算。
★ 注意：现役 `--select-by lowsim_a` 也用 val ⇒ 修此项会**同时改变选中的 epoch** ⇒ 修后需重跑才可与U 比较。

## 3. ★③的定量（清单已自带证据）
`dedup_soft_conflicts.json` 自带：`weight_total_before=3884.0 → weight_total_after=1877.0`
⇒ 那是**未乘 `w_np` 之前**的名义值。实际：`w_tr = w_np[~val_mask] * conf_w`
⇒ 真实组总权重 = `Σ(w_np_i × 1/m)`，**因 `w_np` 本身随类频/CL 保真度变化，组总权重既不恒为 1，各组之间也不相等**。
⇒ ★ **报告表述应改为**："组内权重按组内副本数的倒数设定，名义组总权重为 1；实际梯度贡献还乘以样本级 CL 保真度与类平衡权重。"

## 4. ★④的修法与既有共识
- **修法**：`for f in sorted(d.iterdir()):`（一行）⇒ 行序跨机一致，同 seed 必然选出同一批 val。
- ⚠️ **代码里其实早就知道这个漂移**：`finetune_lora.py:636-641` 明确记录「生成机与训练机的 val 切分随 manifest 行序漂移，属预期」，实测跨机重叠 18/953 ≈ **1.8%**，并已用"跳过不回收"兜住伪标签路径。
- ⇒ ★ **只修 `data.py` 排序不足以消除全部漂移**（清单侧行序也影响），但它是**必要的一环**，且会让伪标签那条"跳过"逻辑变得多余。
- ⚠️ **修此项 = 改变 val 切分 = 改变所有历史 val 读数的可比性** ⇒ 必须与旧读数**分账**（铁律 98），不可混比。

## 9. ★★ uniform 假设的量化风险（我补的，零成本）

**实测训练集真实类分布**（`outputs/oof_local/oof_labels.npy`，148,695 张全覆盖）：
| 指标 | 值 |
|---|---|
| min / max | **5 / 248** 张（**50×**） |
| 中位 / 均值 | 196 / 198.3 |
| SD / CV | 35.5 / **0.179** |

⇒ ★ **官方 L106 说的"存在长尾分布"是实的**（min 5 张 vs max 248 张）。
⇒★★ **关键矛盾**：
- 我们的模型在**长尾训练集**上训练 ⇒ 预测天然偏头部（实测校准前类分布 SD=20.32）；
- 出包链用 `--target uniform` ⇒ **强行把预测类数掰成每类约 49.9**；
- ⇒★ **这条 +1.76pp 的收益，完全押在"测试集真均匀"这个未获官方确认的假设上。**
  若测试集其实也带长尾 ⇒ 掰向均匀就是**过度校正**，收益可能缩水甚至转负。

⇒★ **可零成本验证的方法（用训练集，不碰测试集）**：
1. 留出一份**干净固定切分**（已按 md5 分组的口径），**故意做成与训练集同样的长尾比例**；
2. 在其上比较 `uniform` vs `train` vs `off`（不校正）三种 `--target` 的**整体 Top-1**；
3. ★ **判据只看整体 Top-1，不看预测类分布"平不漂亮"** —— 分布好看不等于正确。
⇒⚠️ 这只能证明"在长尾验证集上哪个 target 更优"，**不能证明测试集真值分布**；
   但它能回答一个有用的问题：**当目标分布未知时，uniform 是安全的默认，还是一个赌注。**
