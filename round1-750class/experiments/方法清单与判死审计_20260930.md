## 二、从**文献**找到的方法（含合规筛选）

> 检索平台：IEEE Xplore / arXiv / Google Scholar / emergentmind（2025 年工作为主）。
> 合规红线（`赛题细则`十一（二）1 逐字）：
> **「测试数据仅可用于测试，不得以自监督、无监督等方式参与到模型训练过程中。」**

### 2.1 ★★ 一条与我们的瓶颈**完全对上**的文献观察

**AttrDD**（*Decoupling Discriminative Attributes for Few-Shot Fine-Grained Recognition*,
IEEE TIP 2025, DOI 10.1109/tip.2025.3573498）原文：

> 「VLMs excel in **excluding most incorrect classes** in fine-grained recognition tasks,
> but **struggles with a small set of confusing categories**, which are typically highly similar subspecies.」

**这正是我们实测的瓶颈**：错分样本 `rank(y)` 中位 = **5.0** ⇒ 绝大多数类已被排除，
卡在一小撮高度相似的类上。⇒ **我们的瓶颈不是"这个任务特有的运气问题"，而是细粒度 VLM 的公认病灶。**

**其解法（两级识别）**：① 先微调选出 **Top-K 困惑类** ② 再用 **LLM 生成的属性差异描述**
做"属性解耦分类"。
⚠️ **②对我们不可用**：我们的类目录名是**纯数字 `0000~0749`** ⇒ 类名无语义 ⇒ 无法生成属性描述。
★ **但 ① 的思路可用**：**"先缩小到困惑类集合，再在集合内做专门判别"**——
第二级用**视觉**证据（不是文本属性）。

### 2.2 ★★★ 可直接落地的一族：GMM 分清洁/噪声 + 软权重 + 原型一致性

| 文献 | 关键机制 | 我们能用的部分 |
|---|---|---|
| **NEARL-CLIP**（Kuchibhotla et al., 2025） | 对**逐样本交叉熵损失**拟合**两分量 GMM**，得到 clean/noisy 概率；用温度锐化后的混合目标；对噪声样本按 KNN 候选集重标定 | ★ **GMM-on-loss 的清洁/噪声二分**——我们是**硬阈值 τ≥0.8**，这是**从没做过的升级** |
| **PICS + NALR**（arXiv 2507.22075, 2025） | **PICS**：用类内特征紧致度 + 类间特征分离度评估伪标签正确性；**NALR**：近邻语义相似度动态精修伪标签；**按估计正确性自适应加权** | ★ **原型一致性投票** + **软权重**（替代硬筛选） |
| **Robust-CLIP**（IJCNN 2025） | 多 prompt 联合预选 + **动态加权**筛可靠子集；SemiLoRA；重标定 + MixMatch；**动态把高置信样本提升进干净集** | ★ **动态（课程式）提升**而非一次性静态筛选 |
| NCU（arXiv 2507.03434, 2025） | 用**最优传输**目标做"遗忘噪声知识" | 机制较远，暂列备选 |

★★ **共同点**：四篇都在做同一件事 —— **把"哪些样本的标签不可信"从"固定阈值"升级成
"统计建模 + 软权重 + 动态更新"**。而我们目前的 `lfix` 用的是**固定 τ≥0.8 硬筛选**。
⇒ **这是一个明确的、有文献背书的升级方向。**

### 2.3 ❌ **合规筛掉的整族方法（省得白花时间）**

| 方法族 | 为什么违规 |
|---|---|
| **Test-Time Adaptation / Test-Time Training (TTA/TTT)** | 在**测试数据**上更新模型 ⇒ 违反「测试数据不得以自监督、无监督等方式参与训练」 |
| **半监督 / 转导（transductive）** | 同上（用测试集做伪标签） |
| **多模型集成 / 模型融合 / 权重平均（soup）** | 十一（一）3 原文点名「不得使用多模型集成、模型融合或多个独立模型投票」（★ 已在 `算法约束核对` 里逐字核对过） |
| 外部数据 / 预训练大模型 API | 十一（二）2、十一（一）2 |
| **文本侧 Prompt Tuning（CoOp）** | 不是违规，而是**无效**：类名是纯数字 ⇒ 文本端无语义 |

★ 注意：我们现在的 **15 视图 TTA 是合法的** —— 它**不更新任何参数**，只是同一模型、同一推理流程内的多次前向聚合，正落在「单一推理流程」里。

## 三、★ 「判死」审计：**真正有榜分铁证的只有 6 个**

### 3.1 审计方法
对每个被关闭的方向，问一句：**当初判死用的是"榜分"还是"本地读数"？**
- 用**榜分** ⇒ 铁证（本项目已多次实测榜分与本地反号）
- 只用**本地读数** ⇒ **严格来说不是"判死"，是"从未被测"**
  （今天刚证实：本地读数**哪怕统计显著**也不能预测榜分 —— `r32` 本地瓶颈桶 +3.58pp / p=0.0025 ⇒ 榜分 **−1.41**）

### 3.2 审计结果

| 方向 | 榜分证据 |

#### ★ 特别标注：`kNN/检索式` 的判死理由**过度解读了**
判死依据是「LoRA 特征 kNN 实测 0.1196 ⇒ **特征端无结构**」。
- **测量本身有效**（kNN 准确率是绝对量，不涉及分层漂移）；
- 但「无结构」是**过度外推**：**同一个特征用 softmax 头能到 0.7462**（OOF 一致率）
  ⇒ kNN 差只说明"该度量空间不适合 kNN"，**不等于特征无结构**。
- ⇒ 结论（不做检索式）**可以维持**，但**理由要改**。

### 3.3 ★★ 审计的总结论

> **我们说的"判死了很多方向"，其中真正有榜分铁证的只有 6 个。**
> **其余大部分是"只被本地读数否掉"，而本地读数已被证明不能预测榜分**
> —— 严格讲，它们是**"从未被测"**，不是"已被判死"。

**而"取最高分"的赛制下，交包只赚不赔**（赛题细则：最终以**排行榜最高得分**为最终成绩）
⇒ **这批"假判死"的方向，正确处置不是继续关闭，而是"排进额度、逐日实测"。**

★ 但必须诚实标注一条约束：**我们不知道哪些包你已经交过了**
（按纪律：涉及用户侧操作的事实，缺记录 ≠ 没发生）。
⇒ 本文只提供**按机制分组的候选池**，交过哪些由你判断。
