## 一、错误本体：两处，都是 `log p` 被写成了 `log y`

### 1.1 官方实现（Wang et al. 2019）——**RCE 含标签**

原论文官方代码 `loss.py`：

```python
def symmetric_cross_entropy(alpha, beta):
    def loss(y_true, y_pred):
        ...
        y_pred_1 = tf.clip_by_value(y_pred_1, 1e-7, 1.0)
        y_true_2 = tf.clip_by_value(y_true_2, 1e-4, 1.0)
        return alpha*tf.reduce_mean(-tf.reduce_sum(y_true_1 * tf.log(y_pred_1), axis=-1)) \
             + beta *tf.reduce_mean(-tf.reduce_sum(y_pred_2 * tf.log(y_true_2), axis=-1))
        #                              ↑ y_pred          ↑ **log(y_true)**  ← 含标签
    return loss
```

⇒ 标准 RCE = **`−Σ_j p_j · log y_j`**
在 one-hot 标签 + `clip(1e-4)` 下 **= 9.21·(1 − p_c)**（`−log(1e-4)≈9.21`）
⇒ **它是"有标签的"：奖励抬高真实类概率。**

### 1.2 我们的实现 —— **RCE 不含标签**

`src/noise.py:252`（`sce_loss`）：

```python
logp = F.log_softmax(logits, dim=1)
ce = F.nll_loss(logp, y, reduction="none")
rce = -(logp.exp() * logp).sum(dim=1)     # ← −Σ p log p  = **预测熵 H(p)**
```

`src/noise.py:296`（`forward_corrected_loss` 的 `sce` 分支）——**同病**，且更明显：

```python
soft = T[y]                      # 软目标就摆在手边
ce = -(soft * logp).sum(dim=1)   # 这一项用对了 soft
...
elif kind == "sce":
    p = logp.exp()
    rce = -(p * logp).sum(dim=1)   # ← 却没用 soft，又变回 log p
```

## 二、冠军链确实在用这个损失

| 证据 | 内容 |
|---|---|
| `src/config.py:289` | `LOSS_KIND = "sce"` ← **默认** |
| `src/config.py:290/316` | `SCE_ALPHA = 0.1`、`SCE_BETA = 0.05` |
| `scripts/chainP_headpool.sh:66-69` | `CHAMP_BASE` **不含 `--kind`** ⇒ 取默认 `sce` |
| `src/finetune_lora.py:1126` | 训练日志打印 `[train] kind={args.kind} ...`（可核对） |

⇒ ★ **74.3 这个分数，是在"CE + 熵最小化"下训出来的，不是在标准 SCE 下。**

**权重下的量级（K=750，α=0.1，β=0.05）**：

| 项 | 值 |
|---|---|
| CE（该项样本） | 7.7083 |
| 我们的 RCE = H(p) | 5.9264 |
| 官方 RCE | 9.2062 |
| 我们的 SCE = 0.1·CE + 0.05·H | **1.0671** |
| 正确的 SCE = 0.1·CE + 0.05·RCE官方 | **1.2311** |
| H 的上界 = log 750 | 6.62 ⇒ 熵项最多贡献 **0.331** |
| CE 项此时 | **0.771** |

⇒ ★ **熵项与 CE 项同量级 ⇒ 不是可忽略的小项。**

## 三、梯度方向：两者**符号相反**（决定性证据）

对 logits 做 autograd（K=750，随机初始化，真实类 = 3）：

| 量 | ∂/∂z_**真实类** | 梯度下降的效果 |
|---|---|---|
| **我们的 RCE = H(p)** | **+0.000800** | **压低**真实类的 logit |
| **官方 RCE** | **−0.004135** | **抬高**真实类的 logit |

对**非真实类**：

| | 前 3 个非真实类 |
|---|---|
| 我们的 | +0.00056、+0.00055、+0.00086（**都为正** ⇒ 下降时一律压低） |
| 官方 | +0.00000、+0.00000、+0.00000（≈0，因 p_c 极小） |

**⇒ 我们这一项是一股"无标签的锐化力"：谁当前 p 大就把谁压得更尖，不管对错。**
**⇒ 官方的这股力是"只在真实类上抬高"。两者不是同一个东西。**

### 3.1 顺带确认：config 注释的解释**方向说反了**

`src/config.py:291` 原文：
> "RCE = -Σ p·log p **完全不含标签**，它唯一的作用就是**把预测分布推向均匀**。
> K 类时 RCE 的极小值**恰好是均匀分布**"

- "完全不含标签" ✅ **对**
- "推向均匀" / "极小值是均匀分布" ❌ **错**
  `H(p) = −Σ p log p` 在单纯形上：**均匀分布给出最大值**（=log K），
  **极小值（0）在 one-hot**。⇒ **最小化 H(p) 是"锐化"，不是"压平"。**

★ 但注释里**观察到的现象是真的**，而且能被解释（见 §四）——**只是解释写反了**。

## 四、"压平/塌缩"现象的机制被我们自己的注释记录过，只是解释错了

`src/config.py:302-310` 实测（K=20 子集 / 800 张 / LoRA）：

| 损失 | val_acc |
|---|---|
| SCE beta=1.0（原默认） | **0.0375 ≈ 1/20** |
| SCE beta=0.2 | 0.2500 |
| **SCE beta=0.05** | **0.5375** |
| 朴素 CE | 0.5312 |
| GCE q=0.7 | 0.2812 |

**用 H(p) 可以定量解释 beta=1.0 的塌缩**（K=20，log K=3.0，CE≈log K=3.0）：

| 策略 | 我们的 SCE（β=1.0） | 我们的 SCE（β=0.05） |
|---|---|---|
| 均匀预测 | 0.1·3.0 + 1.0·3.0 = **3.30** | 0.1·3.0 + 0.05·3.0 = **0.45** |
| 全部预测成同一个类（猜对 1/K） | 0.1·(1/K·0 + (K−1)/K·CE_wrong) + 0 ≈ **1.6** | 同左 ≈ **1.6** |

⇒ **β=1.0 时"塌缩成一个类"（1.6）比"均匀"（3.30）更省 ⇒ 模型选择塌缩** ⇒ 观测到的 acc≈1/K ✅
⇒ **β=0.05 时"均匀"（0.45）比"塌缩"（1.6）更省 ⇒ 塌缩不再划算** ⇒ acc 回到 0.5375 ✅
⇒ ★ **注释里的现象与数字都对，只有"为什么"写反了。**

## 六、诚实的量级判断：**修好能涨多少，我不知道，且不能排除更差**

| 事实 | 含义 |
|---|---|
| 熵最小化（entropy minimization）本身是**半监督学习里的合法技巧**（FixMatch 等的 sharpening） | ⇒ 我们的"错项"**不是纯粹的噪音**，它可能起了正面作用 |
| 它对**正确**的样本是"锐化"，对**错误**的样本是"放大错误" | ⇒ 在含噪数据上方向不明 |
| β=0.05 已把它的量级压到 CE 的 **43%**（0.331 vs 0.771） | ⇒ 影响存在但不是主导 |
| 榜分 90 的队伍不可能靠"修一个损失函数"就到位 | ⇒ **不能**说这个 bug 解释了 15.7pp |

⇒ ★★ **所以正确的动作是"干净对照"，不是"宣布找到了 90 分的钥匙"。**

## 七、要做的实验（用户提议，我同意，并已按此实施）

| 项 | 设计 |
|---|---|
| 自变量 | **只有 RCE 的定义**：`−Σ p log p`（现行）vs `−Σ p log y`（标准） |
| 控制 | **同 seed、同 config、同出包链** |
| 判据 | 榜分（本地尺已多次失效，**不作为裁决**） |
| 成本 | ~100min 训练 + ~25min 出包 ≈ ¥4.5 / 臂 |

**代码处置（用户定调："改就改彻底一点" ⇒ 采用「隔离式」而非「flag 式」）**：

| 动作 | 内容 |
|---|---|
| ✅ **默认改为正确实现** | `sce_loss()` 现在 = **标准 SCE**（RCE = `−Σ p log y`）。`--kind sce` / `LOSS_KIND="sce"` 全部指向它 |
| ✅ **历史实现隔离** | 原实现**逐字冻结**为独立的 `sce_loss_legacy()`，由 `--kind sce_legacy` / `forward_sce_legacy` 调用 |
| ✅ **双向数值自证** | `sce_legacy` vs 历史公式 **差 0.000e+00**；`sce` vs 官方公式 **差 0.000e+00** |
| ✅ 修正 `config.py` 注释 | 「推向均匀」→「无标签**锐化**」，并附塌缩的定量解释 |
| ✅ 更新 `--kind` help | 明确 `sce`=标准、`sce_legacy`=历史 |
| ✅ 更新 `复现说明` | **74.3 对应 `--kind sce_legacy`**（显式、不再依赖"默认"） |

★ 为什么这样更好：**正确的成为默认**（新实验不会再踩坑），
**错的被显式命名**（`*_legacy` 一眼可见，且数值冻结 ⇒ 历史包可复现）。
比"默认保留错的 + 加一个 `_fix` 开关"更干净。

★ ⚠️ **连带影响**：`SCE_BETA = 0.05` 是**为熵项调出来的**经验值。
标准 RCE 的量纲与 H(p) 完全不同（H ∈ [0,6.62]；标准 RCE = 9.21·(1−p_c) ∈ [0,9.21]）
⇒ **换到标准 SCE 后 β 必须重新标定**（官方论文从头训 CNN 用 α=0.1/β=1.0；本任务是微调）。
⇒ 因此 A/B 脚本加了第 4 臂 `--sce-beta 1.0` 测剂量。

## 九、结论（三句）

1. **这是一个确定的实现错误**：RCE 写成了预测熵，梯度方向与标准 SCE **相反**，且在**两处**（`sce_loss`、`forward_corrected_loss`）。
2. **"抗噪族有效 / SCE 已扫完"这两条结论的依据失效**；但**74.3 这个分数仍然有效**——只是它的损失函数要说清是"CE + 熵最小化"。
3. **修好能涨多少分未知，且不能排除更差**（熵最小化本身是 SSL 的合法技巧）。
   ⇒ 优先做**同 seed 的单变量对照**，**不是**先扫 seed 或把 MLP 加到 2048。
